# Strategy and system audit — 2026-11-05

The cloud workflow `system-audit.yml` records a versioned, reproducible baseline
for reviewing observed behaviour against Hamid's charter. Tests, monitored
health and strategy performance are different results; one must not certify
the others.

## Corrections under test

- The active cycle requests actual 4h candles, at least 200 closed 4h/1h bars,
  and rejects insufficient history. The BTC 4h context previously used 1h data.
- Hamid replay models the existing 24h fill and hold windows, both trailing
  steps, configured fees/slippage, and conservative simultaneous stop/target
  handling. It excludes unfilled and right-censored orders and prevents
  overlapping positions. Closed HTF aggregation is aligned to UTC.
- Paper marking ignores the still-open candle, cannot fill after expiry or
  choose a target after the holding deadline, and uses the configured cost
  function for net R. Existing recorded rows are not rewritten.
- Missing, malformed or future feed timestamps fail C5 instead of being
  silently treated as healthy.
- Publication fetches are bounded in time/history and require a common
  ancestor. Snapshot conflicts select the actual newer generation timestamp.
  Failed publication retains an artifact and cannot produce a green heartbeat.
- Both old backtest workflows explicitly use bash pipefail so `tee` cannot
  hide a failed engine. See [Git fetch](https://git-scm.com/docs/git-fetch) and
  [Actions shell behaviour](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#jobsjob_idstepsshell).

## Evidence

`system-audit-evidence`: every offline test module's exit code, duration and
full log; a monitored production snapshot captured before tests; panel and
browser screenshots. The actual Telegram pattern sender is excluded; its
delivery path is tested with mocks. Freebuff tests are included separately.

`real-candle-replay-evidence`: 25 current liquid symbols, 3,000 requested 15m
bars plus HTF warmup for the Hamid component; 12 symbols × 2,000 requested bars
on both 15m/5m for the shipped JS variants. Raw candles, checksums, coverage,
full trade samples and configured costs are retained. Download failure or
invalid/gapped Hamid candles fails that replay; zero trades is reported as
insufficient evidence, never as profitability.

The new Hamid results use `hamid-trades-v2.jsonl`; the old gross-only results
remain intact. The audit's `--isolated` mode does not read or append either
production ledger. There are no API keys, write credentials or order calls in
the audit workflow. LIVE_EXECUTION remains false.

## What a pass does not establish

This is a component replay of stack second-pullback selection plus paper
execution. Historical dominance/news/committee/5m decision packets, historical
universe membership, funding and Bitunix fills are not fully reproduced.
Bootstrap intervals are trade-level, not a cross-symbol dependence correction.
There is no parameter promotion or strategy/risk rule change from these runs.
No claim of 26 healthy independent LLM agents follows from 26 dashboard bindings.

Review `monitored-baseline.json` independently: stale feeds and empty runtime
schemas remain explicit gaps even when deterministic tests are green. Further
review should compare fresh production decisions and their source timestamps
to this baseline, using historical records without mutating them.
